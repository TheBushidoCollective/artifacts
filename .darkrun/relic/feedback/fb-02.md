## `every-cited-url-resolves` fails open on the last line of the manifest

Both `frame-artifact` and `frame-preconditions` carry the identical gate, and in both it can pass while a fabricated URL goes entirely unchecked.

The gate reads the manifest with `while IFS= read -r u; do ... done < docs/frame.sources.txt`. When the manifest has no trailing newline, `read` consumes the final line, sets `$u`, and returns non-zero. The `while` condition is therefore false, so the loop body never runs for that line. The last URL is never curled.

Worse, gate 3 and gate 4 disagree about what the manifest contains. `grep -c .` counts the final unterminated line; the `while read` loop drops it. A 6-line manifest passes `sources-manifest-populated` on a count of 6 while `every-cited-url-resolves` verifies only 5.

### Proof (run in a scratch directory, macOS, bash 5.3.3, curl 8.7.1)

```
$ printf 'https://example.com/\nhttps://this-domain-does-not-exist-xyzzy-9812.invalid/' > nonl.txt
$ grep -c . nonl.txt
2
$ bash -c 'set -eu; while IFS= read -r u; do [ -n "$u" ] || continue; echo "checking: $u"; curl -sfL --max-time 25 --retry 2 -A "Mozilla/5.0 (relic-link-check)" -o /dev/null "$u"; done < nonl.txt'
checking: https://example.com/
exit=0
```

The invalid URL on line 2 was never checked, and the gate passed.

The unit body says of this gate: "A fabricated URL fails this gate, which is the point." As written, a fabricated URL on the final line does not fail it. Whether a manifest ends in a newline is an artifact of how the executing agent happens to write the file, not a decision anyone makes, so this is a coin flip on every run.

### The fix (one clause)

Make the loop condition accept a final unterminated line:

```
bash -c 'set -eu; while IFS= read -r u || [ -n "$u" ]; do [ -n "$u" ] || continue; curl -sfL --max-time 25 --retry 2 -A "Mozilla/5.0 (relic-link-check)" -o /dev/null "$u"; done < docs/frame.sources.txt'
```

Verified against the same unterminated fixture: exit 6 (`CURLE_COULDNT_RESOLVE_HOST`), both URLs checked. Verified against a well-formed manifest ending in a newline: exit 0, exactly two iterations, terminates cleanly (no infinite loop, because `read` clears `$u` at true EOF).

Apply the identical change to `frame-preconditions`'s `every-cited-url-resolves`, which reads `docs/preconditions.sources.txt`.

### What I checked that is sound, and needs no change

- **`set -eu` does propagate a curl failure out of the `while` loop.** The loop body is not an exempt context, so `set -e` fires. Verified: exit 6.
- **`grep -c .` behaves as intended on a file with no trailing newline.** It counts the unterminated final line. Verified: 3 for both a terminated and an unterminated 3-line file.
- **`test "$(wc -w < docs/frame.md)" -ge 900` is sound.** BSD `wc` emits leading whitespace (`[       3]`), but bash `test -ge` skips it and compares as an integer. Verified both the true and false branches.
- **The network gate is not flaky against this evidence base.** I ran the exact gate curl against all 51 distinct URLs in the ten recorded knowledge topics. Every one returned HTTP 200 with rc=0, including arxiv PDFs, Google support and docs pages, `learn.microsoft.com`, `portswigger.net`, `bughunters.google.com`, `uscode.house.gov`, and GitHub. The `-L`, `--retry 2`, `--max-time 25`, and browser user-agent combination is doing its job. No 403s, no rate limiting, no redirect-chain failures.
- **The `depends_on: ["frame-artifact"]` edge is sufficient** for `docs/frame.md` to exist in `frame-preconditions`'s worktree when its gates run. `wave_ready` (`crates/darkrun-mcp/src/position.rs:551`) gates a unit on all its dependencies being complete; `enter_unit` (`crates/darkrun-mcp/src/lifecycle.rs:371`) forks the unit worktree off the station branch at entry time; `land_unit` (`crates/darkrun-mcp/src/lifecycle.rs:468`) merges the unit branch back onto the station branch when the unit locks. `frame-preconditions` is therefore entered only after `frame-artifact` has landed on `darkrun/relic/frame`. Neither unit's gates reference a sibling's output, so there is no collision even though both write under `docs/`.
- **The word-count and source floors are achievable without padding.** 900 words across five sections with the specified content, and 700 across five sections one of which enumerates twelve controls with a rationale line each, are both comfortably covered by the recorded material. The 6-source and 5-source floors draw from a pool of 51 verified live URLs.
