TESTABILITY REVIEW (pre-manufacture, `specify` spec): the sixteen gates are sound. One defect, in all four units, in the instruction that loads the station's only inputs.

## The `Read first` command fails with a fatal error in all four units

Every one of `spec-relic-format`, `spec-publish-contract`, `spec-viewer`, and `spec-service-surface` instructs the worker to read the locked artifacts with:

```
git show darkrun/relic/frame:docs/frame.md
git show darkrun/relic/frame:docs/preconditions.md
```

Both commands fail. There is no local ref `darkrun/relic/frame`.

### Proof (repo root, `/Users/jwaldrip/dev/src/github.com/thebushidocollective/artifacts`)

```
$ git show darkrun/relic/frame:docs/frame.md
fatal: invalid object name 'darkrun/relic/frame'.
$ echo $?
128

$ git for-each-ref --format='%(refname)' | grep darkrun
refs/heads/darkrun/relic/main
refs/heads/darkrun/relic/specify
refs/remotes/origin/darkrun/relic/frame
refs/remotes/origin/darkrun/relic/main
refs/remotes/origin/darkrun/relic/units/frame/frame-artifact
refs/remotes/origin/darkrun/relic/units/frame/frame-preconditions
```

The frame station branch survives only as a remote-tracking ref. `git show origin/darkrun/relic/frame:docs/frame.md` exits 0. The form written into the units exits 128. Worktrees share the repository's ref database, so a unit worktree forked from `darkrun/relic/specify` will not have the local ref either. This fails identically in all four units, on every run, at the first step.

### The instruction is also unnecessary, which is the part worth fixing

Both files are already in the worktree. They are on the station branch:

```
$ git ls-tree -r --name-only darkrun/relic/specify -- docs
docs/frame.md
docs/frame.sources.txt
docs/preconditions.md
docs/preconditions.sources.txt
```

And they are byte-identical to the frame-branch copies, same blob SHAs in both trees:

```
docs/frame.md          specify=4574698e  frame=4574698e  IDENTICAL
docs/preconditions.md  specify=746a12f1  frame=746a12f1  IDENTICAL
```

So the units route the worker through a broken indirection to reach files sitting in the working directory. `cat docs/frame.md` works and returns the same bytes.

### Why this matters beyond the inconvenience

The failure is loud, so it will not silently corrupt output the way `fb-02` could. The risk is different. These two documents are the station's entire input, and each unit body carries an "Already decided. Do not relitigate." section whose authority rests on the worker having read them. A worker that hits `fatal: invalid object name` on the first instruction, with no stated fallback, may conclude the input is unavailable and proceed on the unit body alone. Every locked constraint the worker then relitigates is drift that the review beats have to catch downstream.

The units also declare inputs that do not name a readable path: `spec-relic-format` declares `frame.md`, and the real path is `docs/frame.md`. The three dependents declare `docs/spec/format.md`, which is correct and genuinely produced by `spec-relic-format`. Only the frame-station input is mislabeled.

### FIX

In all four unit bodies, replace the `git show` block with a direct read from the worktree, and say why it is safe:

```
Read the locked artifacts, read-only, from the repo root:

  docs/frame.md
  docs/preconditions.md

Both are already on this station's branch and are byte-identical to the
frame station's locked copies. Do not edit them.
```

If the indirection is wanted for provenance, `origin/darkrun/relic/frame` is the ref that resolves, but the direct read is better: it needs no ref, no fetch, and no network.
