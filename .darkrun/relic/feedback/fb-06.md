TESTABILITY RE-REVIEW after `fb-05`. The read-path fix is correct for the two locked upstream artifacts. It is wrong for sibling outputs, and it removed the only workaround that got the previous station through this exact problem.

## Three units assert a sibling's output is in their worktree. This run's only precedent says it will not be.

The revised bodies now say:

- `spec-viewer`: "**in your own worktree** (all three files are present there; **do not use `git show`**)" and lists `docs/spec/format.md`.
- `spec-service-surface`: same instruction, lists `docs/spec/format.md`.
- `spec-publish-contract`: "**in your own worktree** (all four files are present there; **do not use `git show`**)" and lists `docs/spec/format.md` **and** `docs/spec/service.md`.

`docs/frame.md` and `docs/preconditions.md` really are on the station branch, so that half of the fix is right and I verified it again. The sibling-output half rests on an engine behavior that has never been observed working in this run, and was observed failing.

### Proven, from the `frame` station

`frame-preconditions` declared `depends_on: ["frame-artifact"]` and `inputs: ["docs/frame.md"]`, exactly the shape the three dependent `specify` units now use. Its worktree did not contain that input.

```
$ git ls-tree -r --name-only origin/darkrun/relic/units/frame/frame-preconditions
.claude/settings.json
.gitignore
docs/preconditions.md
docs/preconditions.sources.txt

$ git cat-file -e origin/darkrun/relic/units/frame/frame-preconditions:docs/frame.md; echo $?
1

$ git merge-base --is-ancestor \
    origin/darkrun/relic/units/frame/frame-artifact \
    origin/darkrun/relic/units/frame/frame-preconditions; echo $?
1
```

The merge-base of the two unit branches does not contain `docs/frame.md` either. The dependent forked from a point that did not have its dependency's output.

All three worker beats reported it independently, in their own iteration notes:

- **Framer:** "STRUCTURAL ISSUE, verified, not the framer's fault. `docs/frame.md` was **not present in this unit's worktree**, despite being its declared input."
- **Challenger:** "`docs/frame.md` is still not in the worktree; read it via `git show darkrun/relic/units/frame/frame-artifact:docs/frame.md`, read-only."
- **Distiller:** "`docs/frame.md` still is not in this worktree and `frame-artifact`'s output has not landed on the station branch. All three beats read it via `git show ...`. **The two units' outputs are on branches that have never met.**"

**Every beat of that unit survived by using `git show` against the sibling unit branch.** That is precisely the escape the revised bodies now forbid by name.

### What is unproven, and why that is the problem

The landing bug is genuinely fixed: `docs/frame.md` and `docs/preconditions.md` are on `darkrun/relic/specify` today, byte-identical to the frame-branch copies. So station-branch landing works now.

Whether the engine forks a dependent unit's worktree **after** its dependency lands is a different question, and I cannot test it: all four `specify` units are `pending` and no `units/specify/*` refs exist yet.

The defect is the combination, not either half alone. The bodies state an unverified engine behavior as fact ("all four files are present there") **and** remove the recovery path ("do not use `git show`"). If the fork timing is not fixed, a compliant worker finds no input, is forbidden the one method that worked last station, and has no sanctioned fallback.

### What breaks if the assumption is wrong

These criteria are unsatisfiable without actually reading the sibling output, so they fail rather than degrade:

- `spec-publish-contract` criterion 11: "Every publish failure maps onto a status and named machine-readable fields from `docs/spec/service.md`, **with no status invented here**." Needs `service.md`.
- `spec-viewer` criterion 15: consistency with `format.md` on fragment stripping. Needs `format.md`.
- `spec-service-surface` criterion 7: the expired-versus-never-existed decision must reference `format.md`'s ID entropy decision. Needs `format.md`.

`spec-publish-contract` is worst placed: it declares two sibling inputs and would be missing both.

The likely silent failure is worse than the loud one. A worker that cannot read `format.md` and is told not to use `git show` may simply write the sections anyway, redefining the ID or container, which every one of these units explicitly forbids.

### FIX

Keep the direct-read instruction, drop the blanket `git show` prohibition, and give a fallback that is correct under either engine behavior. In the three dependent units:

```
Read `docs/spec/format.md` (and `docs/spec/service.md`, for spec-publish-contract)
from your worktree. If a declared input is not present there, read it from the
station branch instead:

  git show darkrun/relic/specify:docs/spec/format.md

Do not use `git show darkrun/relic/frame:...`; that ref does not resolve.
Never proceed past a missing declared input by writing the section anyway.
```

Narrowing the prohibition to the ref that actually fails keeps `fb-05`'s correction intact without removing the recovery path.
