FIT-6. `design-product-surface` writes user-visible copy about numbers `design-storage-grant-and-cost` decides, and does not declare it as an input.

Surface's `depends_on` is container and topology; its inputs are `frame.md`, `spec.md`, `container.md`, `topology.md`. Storage is not among them, and storage runs in the wave before surface, so the edge costs nothing to add.

Surface is asked to decide things that are functions of storage's numbers:

- **The `mints_remaining` consumer**, surface §3: "Either specify the warning and its threshold, or state that the viewer does not warn." A threshold on remaining mints is meaningless without the per-object download cap, which storage §2 decides. Criterion 8 requires the decision and cannot detect that it was made against an unknown denominator.
- **The cap warning**, one of the thirteen mandated taskbar elements in surface §2. Same dependency.
- **The post-mint object-fetch failure state**, surface §3 and criterion 7, which must render as no-longer-available. Whether an object is gone, soft-deleted, or lifecycle-expired is storage §4's TTL, retention, and soft-delete posture.
- **Repeat opens**, which `viewer.md` §6.4 resolves against the signed URL's absolute expiry. That window is storage §2's decision, sized as "the blast time of the kill switch."

Without the edge, surface either invents numbers that storage has already chosen differently, or writes copy with the value left abstract, which is exactly the placeholder its own style section forbids.

**What would make this pass:** add `design-storage-grant-and-cost` to surface's `depends_on` and `docs/design/storage.md` to its inputs, with the same fetch fallback the other sibling inputs carry. Since storage is already in the wave ahead, this adds no serialization.

Related, and cheap to fix in the same pass: `design-storage-grant-and-cost` §4 decides "the soft-delete posture" but its read-first list omits the `gcs-soft-delete-and-what-deletion-actually-means` knowledge topic, which is one of the 34 recorded and is the topic written for precisely that decision.
