Unit `design-operations-and-abuse`, `docs/design/operations.md` section 2.3. The automated same-sentence co-occurrence matcher for personal-data reports (branch B, no dedicated form category) is unearned complexity.

The document's own closing paragraph of section 2.3 states the mandatory screen at section 2.2 item 1 "reads every report's free text end to end regardless of what the matcher does or does not catch" and names it "the backstop for both gaps, the adjacency miss and the language miss." The screen already runs on every single report, at intake, before any automated step fires, including deletion (section 2.2 item 1: "Every report that reaches `/abuse` or the alias is read by the operator, or the named backup, before section 2.1's automated steps fire on it"). The matcher's only other stated value is that it "routes the common case fast," and that claim does not survive scrutiny: the screen already happens immediately for every report, so there is no latency the matcher saves that the screen does not already spend on the same report at the same moment.

By the document's own stated logic, the matcher and the screen exist to catch the identical failure, a free-text personal-data claim going unrouted, and the second mechanism it names (the screen) already fully covers what the first (the matcher) claims to catch. That is two guards for one failure, not two guards for two failures, which is the distinction the station has correctly applied elsewhere (surface.md's byte cap plus single-line guard answer two different failure modes named separately in `viewer.md` 3.3 and the design brief; this pairing answers only one).

Remove it: fold branch B's personal-data detection entirely into the existing mandatory screen, with no separate automated subsystem, no possessive-noun heuristic to maintain, and no separately named adjacency-miss or English-only residual risk to carry into the disclosure statement, since the screen was never scoped by language and reads full sentences rather than matching a pattern.

The criterion that still passes without it: criterion 7, "specifies the data-subject report path against both branches of the form's category question, naming design-product-surface as the owner of the category itself." Branch A's path (dedicated category, direct routing) is untouched. Branch B's path becomes "detected by the screen, which already reads every report's free text end to end before any automated step fires," which is a shorter and, on the document's own coverage claim for the screen, equally complete specification.
